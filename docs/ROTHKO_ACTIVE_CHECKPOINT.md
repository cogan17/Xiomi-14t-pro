## Current milestone — Native ADB precommit and late-load admission (2026-10-14)

Parent branch head: `53bfe6c499bd529852947fe361522f3ef6455bab`. Audit pin remains `pershoot/KernelSU-Next@3438d6aa431f96a23f9e625bec3d53ce1fb14161`. Draft / BUILD HOLD. Parent documentation changes, including usage-limit policy, are preserved.

The selected order is now **24 stages**. Its actual sucompat dependency is caller-status stage 20; the independent backup stage is preserved without inventing a new dependency gate.
- The old committing void ADB helper becomes `ksu_prepare_adb_root_cred(struct cred **out)`. It initializes out to NULL, prepares a private credential, requires global euid root plus init domain, propagates domain errno and validates the resulting KSU domain. Every failed owned preparation aborts once. Success transfers only an unpublished credential to its caller.
- Shared ADB commit code performs credential preparation -> native envp staging -> **one** credential commit -> caller-local output. The dispatcher publishes its kernel envp/register pointer only after success. Negative filename/library results propagate. On staging failure the credential aborts and the external exec pointer remains unchanged.
- **Intentional semantics:** native ADB retains existing UID, groups and capabilities, changing the SELinux domain for the admitted init-domain root child. The ineffective second SUSFS root-profile transaction is removed; this is not general profile escape equivalence.
- One native builder accepts NULL envp as empty, limits original entries to **4096** plus two LD variables and a terminator, checks native pointer address overflow, requires a terminator, and checks all three stack subtractions/alignment and user copies. Only a successful complete frame is returned through the local output. Short/failing copies can leave partial user-stack bytes; no user-memory rollback is claimed.
- SUSFS ADB now carries an explicit typed `bool is_compat` from all three caller branches. Matching COMPAT requests fail with `-EOPNOTSUPP` before library/credential/user-pointer work. The native syscall bridge uses `in_compat_syscall()`; its selected BSP definition was verified once in [include/linux/compat.h](https://github.com/cogan17/Xiomi-14t-pro/blob/b2d8b54a0d8bb002d32dda24e58d2b5d0423546b/include/linux/compat.h), blob `594357881b0b3b5a0e06d9c07a6626fc4a517a2a`.
- `kernelsu_init()` rejects `MODULE && current->pid != 1` with `-EOPNOTSUPP` before `susfs_init()`, credential/resource initialization and registrations. Built-in/PID1 module admission is preserved. The earlier stack-protector trampoline can initialize RNG/module canary before this entry; no zero-side-effect or complete unwind claim is made. Do not call `kernelsu_exit()` for this early rejection.
