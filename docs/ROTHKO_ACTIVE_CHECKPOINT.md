## Current milestone — KSUN preparation and internal escape caller errors (2026-10-14)

Parent branch: `f4ab84456407b9d533d8081656818345c4e3868b`. Audit pin remains `pershoot/KernelSU-Next@3438d6aa431f96a23f9e625bec3d53ce1fb14161`. Draft / BUILD HOLD. No existing candidate is overwritten.

- New `patches/rothko-ksun-app-profile-precommit-composable-candidate.patch` composes the existing groups fail-closed and seccomp preallocation intentions after the verified 18-stage base, without duplicate SELinux/namespace API hunks. Groups/ucounts errors abort before commit. Already-root returns `-EALREADY` and disabled escape returns `-EPERM` in both configurations, rather than falsely reporting a fresh grant.
- Scratch is allocated unconditionally after checked groups/SELinux and before the single credential commit: one extra `task_struct` allocation per successful profile escape. This ensures scratch exists even if a filter is added before the later check; it does not prove concurrent seccomp semantics. Success/abort each free scratch once. The public allocation-based `disable_seccomp` wrapper remains for setuid callers; their allocation/lifecycle contract remains unresolved.
- New `patches/rothko-ksun-su-escape-caller-status-candidate.patch` allocates a replacement filename before escape and transfers it only after checked success. Exact failures release replacement and consume pending audit events. Valid custom profile UID/domain is retained; the older hardcoded-root/domain alternative is preserved but not stacked.
- The FD/register caller checks its userspace empty-path write before escape, and edits registers only after success. Installed FDs close on error; the already-returned shared borrow is not returned twice. Existing post-exec-error register restoration stays intact. This does not solve credentials already committed when exec itself fails or authorize a SU_SESSION FD.
- Init helper sentinel is now positive for ordinary exec, zero for handled success and negative for exact error. User argv is checked before init escape. Its predicate uses borrowed `current_cred()` rather than leaking a reference via `get_current_cred()`. The non-SUSFS bridge returns init/ADB errors and consumes its pending event before each failing return. ADB's own helper/transaction is not made safe by this bridge change.
- `tests/test_rothko_ksun_escape_precommit.py` defines the **20-stage** order: existing 18-stage base -> new app-profile preparation candidate -> new caller candidate. One focused run passed ordinary strict forward/reverse checks, **20 negative mutations**, duplicate-apply rejection for both new patches, and exact pinned-byte restoration for **13 source files**. Only inherited zero-context G1 uses `--unidiff-zero`. No recount, whitespace relaxation, kernel build, broad green-audit rerun or CI dispatch.
